Задание 2. Связь «один к одному»: User и Profile

Сценарий: у пользователя ровно один профиль (аватар, био, город, соцсети).

Схема Profile (models/Profile.js).
Поле avatarUrl должно быть строкой и обрезаться от пробелов по краям.
Поле bio должно быть строкой, обрезаться от пробелов по краям и иметь максимальную длину 500 символов.
Поле city должно быть строкой, обрезаться от пробелов по краям и иметь максимальную длину 100 символов.
Поле country должно быть строкой, обрезаться от пробелов по краям и иметь максимальную длину 100 символов.
Поле birthdate должно быть датой, и значение не может быть в будущем - добавьте кастомный валидатор.
Поле website должно быть строкой и обрезаться от пробелов по краям.
Поле socials должно быть поддокументом с тремя полями: telegram, github и linkedin, каждое из которых является строкой и обрезается от пробелов по краям.
Поле user должно быть ссылкой на модель User (через ref), быть обязательным и уникальным - именно уникальность обеспечивает связь «один к одному».
У схемы включите опцию timestamps: true.
Создайте модель с именем Profile на основе этой схемы и экспортируйте её.

Правка схемы User (models/User.js).
Добавьте в схему поле profile, которое является ссылкой на модель Profile (через ref) и не является обязательным.
Экспорт модели User не меняется.

Задание 3. Связь «один ко многим» с двумя уровнями: User → Post → Comment

Сценарий: у пользователя много постов, у поста много комментариев; у комментария тоже есть автор (тоже User).

Схема Post (models/Post.js).
Поле title должно быть строкой, обязательным, обрезаться от пробелов по краям, иметь минимальную длину 3 символа и максимальную 150.
Поле content должно быть строкой, обязательным, иметь минимальную длину 10 символов и максимальную 10000.
Поле tags должно быть массивом строк, каждая строка обрезается от пробелов по краям, приводится к нижнему регистру и имеет максимальную длину 30 символов; добавьте кастомную валидацию, что тегов не больше 10.
Поле views должно быть числом, по умолчанию 0, и не может быть отрицательным.
Поле isPublished должно быть булевым значением и по умолчанию равно false.
Поле publishedAt должно быть датой и по умолчанию равно null.
Поле author должно быть ссылкой на модель User (через ref) и быть обязательным.
Поле comments должно быть массивом ссылок на модель Comment (через ref) и по умолчанию быть пустым массивом.
У схемы включите опцию timestamps: true.
Создайте модель с именем Post и экспортируйте её.

Схема Comment (models/Comment.js).
Поле text должно быть строкой, обязательным, обрезаться от пробелов по краям, иметь минимальную длину 1 символ и максимальную 1000.
Поле likes должно быть числом, по умолчанию 0, и не может быть отрицательным.
Поле isEdited должно быть булевым значением и по умолчанию равно false.
Поле post должно быть ссылкой на модель Post (через ref) и быть обязательным.
Поле author должно быть ссылкой на модель User (через ref) и быть обязательным.
У схемы включите опцию timestamps: true.
Создайте модель с именем Comment и экспортируйте её.

Задание 4. Самоссылающаяся связь «многие ко многим»: User и User (подписки)

Сценарий: пользователи подписываются друг на друга. Одна и та же модель ссылается сама на себя.

Правка схемы User (models/User.js) — добавьте два поля.
Поле followers должно быть массивом ссылок на модель User (через ref) и по умолчанию быть пустым массивом.
Поле following должно быть массивом ссылок на модель User (через ref) и по умолчанию быть пустым массивом.

Дополнительно расширьте схему User полями (если ещё не добавлены).
Поле bio должно быть строкой, обрезаться от пробелов по краям и иметь максимальную длину 300 символов.
Поле avatarUrl должно быть строкой и обрезаться от пробелов по краям.
Поле lastLoginAt должно быть датой и по умолчанию равно null.

Задание 5. M:N через промежуточную сущность с данными: Order и Product

Сценарий: заказ содержит несколько товаров, у каждого — своё количество и цена на момент покупки. Это «многие ко многим» с дополнительными полями на связи.

Схема Product (models/Product.js).
Поле name должно быть строкой, обязательным, обрезаться от пробелов по краям, иметь минимальную длину 2 символа и максимальную 100.
Поле description должно быть строкой, обрезаться от пробелов по краям и иметь максимальную длину 1000 символов.
Поле price должно быть числом, обязательным и не может быть отрицательным.
Поле stock должно быть числом, по умолчанию 0, и не может быть отрицательным.
Поле sku должно быть строкой, обязательным, уникальным, обрезаться от пробелов по краям и автоматически приводиться к верхнему регистру.
Поле category должно быть строкой, принимать только одно из значений books, clothing, accessories или other, и по умолчанию равно other.
Поле isAvailable должно быть булевым значением и по умолчанию равно true.
У схемы включите опцию timestamps: true.
Создайте модель с именем Product и экспортируйте её.

Схема Order (models/Order.js).
Поле user должно быть ссылкой на модель User (через ref) и быть обязательным.
Поле items должно быть массивом поддокументов. В каждом поддокументе:
product - ссылка на модель Product (через ref), обязательная;
quantity - число, по умолчанию 1, не меньше 1 и не больше 100;
priceAtPurchase - число, обязательное и не может быть отрицательным.
Добавьте кастомную валидацию на весь массив items: он обязателен и должен содержать хотя бы один элемент.
Поле status должно быть строкой, принимать только одно из значений pending, paid, shipped, delivered или cancelled, и по умолчанию равно pending.
Поле total должно быть числом, обязательным и не может быть отрицательным.
Поле shippingAddress должно быть поддокументом с тремя полями: city, street и zip. Каждое из них — строка, обязательная, обрезается от пробелов по краям и имеет ограничение по длине (city и street — до 100 символов, zip — до 20).
Поле paidAt должно быть датой и по умолчанию равно null.
У схемы включите опцию timestamps: true.
Создайте модель с именем Order и экспортируйте её.
